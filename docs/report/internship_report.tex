{\LARGE\bfseries ABSTRACT}\\[2cm]
\end{center}

The digital presence of educational institutions has become crucial in today's technology-driven world. This report documents the comprehensive development of the official website for National Institute of Technology (NIT) Goa, one of India's premier technical institutions.

\vspace{0.5cm}

The project encompasses the design, development, and deployment of a modern, responsive, and feature-rich web platform serving multiple stakeholders including prospective students, current students, faculty members, staff, and visitors. Built using cutting-edge technologies including React.js 19.1.0 for the frontend and Express.js with Node.js for the backend, the website implements a sophisticated monorepo architecture ensuring scalability and maintainability.

\vspace{0.5cm}

The implementation includes \textbf{35+ functional pages} covering academic programs, departments, faculty directory with \textbf{75+ faculty profiles}, administration, admissions, research, and facilities. A distinctive ``Liquid Glass'' user interface inspired by Apple's design philosophy provides an elegant and intuitive user experience across all devices.

\vspace{0.5cm}

Key technical achievements include an advanced faculty directory with department-specific filtering, a dynamic 17-image carousel on the homepage, automated announcement system, responsive design implementation, and a robust backend API architecture. Security features such as CORS protection, rate limiting, and JWT-based authentication ensure data protection and system integrity.

\vspace{0.5cm}

The project utilizes modern development practices including npm workspaces for monorepo management, cross-platform development scripts, Firebase hosting for deployment, and comprehensive version control through Git and GitHub. The demo version of the NIT Goa website is now live at https://nit-goa-ac-in.web.app, serving as a preview of the institute’s digital gateway.

\vspace{0.5cm}

This report details the complete development lifecycle including requirement analysis, system design, implementation, testing, deployment, and future enhancement plans. The project demonstrates the practical application of full-stack web development principles and serves as a sustainable foundation for NIT Goa's digital infrastructure.

\vspace{1cm}

\noindent\textbf{Keywords:} Web Development, React.js, Express.js, Educational Portal, Full-Stack Development, Responsive Design, NIT Goa

\chapter{Introduction}

\section{Background \& Motivation}

\subsection*{About NIT Goa}

National Institute of Technology Goa, established in 2010, is one of the 31 National Institutes of Technology in India and is recognised as an Institute of National Importance under the NIT Act, 2007. Located at Kottamoll Plateau, Cuncolim Municipal Area, Salcete Taluka, South Goa District, Goa - 403703, the institute has rapidly grown to become a centre of excellence in technical education and research. NIT Goa offers undergraduate, postgraduate and doctoral programmes across multiple engineering disciplines and sciences.

\subsection*{The Digital Imperative}

The need for a comprehensive, modern, and functional website for NIT Goa arose from several critical factors:

\begin{enumerate}
    \item \textbf{Information Accessibility:} With thousands of prospective students, current students, faculty members, researchers, and other stakeholders seeking information daily, a centralized, well-organized digital platform became essential.

    \item \textbf{Institutional Identity:} As NIT Goa continues to establish itself among India's premier technical institutions, a professional web presence that reflects the institute's values, achievements, and capabilities is crucial for building and maintaining reputation.

    \item \textbf{Administrative Efficiency:} A properly designed website can significantly reduce the administrative burden by providing self-service information access, reducing repetitive queries, and streamlining communication channels.

    \item \textbf{Global Reach:} With increasing emphasis on internationalization of education, the website serves as a window to the world, enabling global collaborations, international student recruitment, and showcasing research outputs to a worldwide audience.
\end{enumerate}

\subsection*{Evolution of Web Presence}

Prior to this project, NIT Goa's digital presence faced several limitations:
\begin{itemize}
    \item Outdated design not aligned with modern web standards
    \item Limited mobile responsiveness affecting user experience
    \item Incomplete information across various sections
    \item Lack of dynamic content management capabilities
    \item Inconsistent user interface across different pages
    \item Limited integration with backend systems for real-time updates
\end{itemize}

\subsection*{Project Genesis}

Recognizing these challenges, the initiative to develop a comprehensive, modern website for NIT Goa was undertaken. The project aimed not just to create a website, but to build a sustainable digital infrastructure that could evolve with the institution's growing needs.

\vspace{0.5cm}

The motivation for this project stemmed from:
\begin{itemize}
    \item Personal commitment to contribute meaningfully to the institution
    \item Opportunity to apply full-stack development skills in a real-world, high-impact project
    \item Desire to create a lasting digital asset for the NIT Goa community
    \item Recognition of the importance of digital presence in modern education
\end{itemize}

This report documents the journey from concept to deployment, detailing the technical decisions, implementation strategies, challenges overcome, and lessons learned in creating a fully developed website for the National Institute of Technology Goa, which is currently undergoing review and final refinements before official approval.

\section{Problem Statement}

The development of the NIT Goa website addressed several critical problems and requirements that were identified through stakeholder analysis, competitive benchmarking, and assessment of current digital infrastructure limitations.

\subsection*{Primary Problems Identified}

\subsubsection*{1. Information Fragmentation}
\begin{itemize}
    \item Essential information scattered across multiple informal sources
    \item No single authoritative source for institutional information
    \item Difficulty in locating specific details about programs, faculty, or facilities
    \item Inconsistent and often outdated information across different platforms
\end{itemize}

\subsubsection*{2. Poor User Experience}
\begin{itemize}
    \item Non-responsive design failing on mobile devices (used by 60\%+ of visitors)
    \item Cluttered layouts with poor information hierarchy
    \item Slow loading times affecting user engagement
\end{itemize}

\subsubsection*{3. Limited Stakeholder Support}
\textbf{For Faculty \& Staff:}
\begin{itemize}
    \item Inability to update personal profiles and achievements
\end{itemize}
\textbf{For Students:}
\begin{itemize}
    \item Difficult access to academic regulations and curriculum details
    \item No centralized repository for notices and announcements
    \item Limited information about department-specific resources
    \item Absence of quick links to frequently needed services
\end{itemize}

\subsubsection*{4. Technical Deficiencies}

\textbf{Infrastructure Issues:}
\begin{itemize}
    \item Legacy technology stack difficult to maintain
    \item No version control or proper development workflow
    \item Lack of scalability for future growth
\end{itemize}
\textbf{Performance Problems:}
\begin{itemize}
    \item Slow page load times (>5 seconds average)
    \item No content delivery optimization
    \item Inefficient database queries
    \item Absence of caching mechanisms
\end{itemize}

\subsubsection*{5. Content Management Challenges}
\begin{itemize}
    \item Manual HTML editing required for content updates
    \item Dependency on technical staff for routine updates
    % \item No workflow for content approval and publishing
    \item Difficulty in maintaining content consistency
\end{itemize}

\subsubsection*{6. Analytics \& Insights}
\begin{itemize}
    \item Lack of proper visitor analytics
    \item No information on device-specific traffic (desktop, mobile, tablet)
\end{itemize}

\subsection*{The Challenge}

The core challenge was to design and develop a comprehensive web platform that:
\begin{itemize}
    \item Addresses all identified problems systematically
    \item Meets diverse stakeholder requirements
    \item Implements modern web technologies and best practices
    \item Provides excellent user experience across all devices
    \item Ensures scalability, security, and maintainability
    \item Establishes foundation for future enhancements
\end{itemize}

\section{Project Objectives}

Based on the identified problems and stakeholder requirements, the following objectives were established for the NIT Goa website development project:

\subsection*{Primary Objectives}

\begin{enumerate}
    \item \textbf{Develop a comprehensive institutional website} with 35+ pages covering academics, admissions, faculty, and administration to serve as the single source of truth for NIT Goa information.
    
    \item \textbf{Build an advanced faculty directory and profile management system} enabling 75+ faculty members to maintain their professional profiles with department-wise filtering, HOD highlighting, and self-service profile updates through secure JWT-based authentication.
    
    \item \textbf{Build a scalable full-stack architecture} using React.js frontend, Express.js backend, and MySQL database with RESTful API design.
    
    \item \textbf{Achieve optimal performance} with page load times under 3 seconds and Lighthouse scores above 85.
\end{enumerate}

\subsection*{Secondary Objectives}

\begin{enumerate}
    \item \textbf{Implement secure authentication and authorization} using JWT tokens, enabling faculty to log in and manage their profiles, research areas, publications, and photographs.
    
    \item \textbf{Establish robust security measures} including CORS protection, rate limiting, input validation, and protection against web vulnerabilities.
    
    \item \textbf{Ensure search engine optimization} through semantic HTML, meta tags, and structured data implementation.
    
    \item \textbf{Create comprehensive documentation} covering installation, API specifications, authentication flows, and maintenance guidelines.
\end{enumerate}

\section{Analysis of Similar Institutional Websites}

Before beginning the development, a comprehensive analysis of websites from other NITs and IITs was conducted to understand best practices, common features, and areas for improvement.

\subsection*{Websites Analyzed}
\begin{itemize}
    \item NIT Trichy, NIT Warangal, NIT Surathkal
    \item IIT Bombay, IIT Madras, IIT Delhi
    \item International institutions: MIT, Stanford
\end{itemize}

\subsection*{Key Observations}
\begin{enumerate}
    \item \textbf{Navigation Patterns:} Most sites use hierarchical mega-menus with clear categorization
    \item \textbf{Faculty Directories:} Department-wise listing is standard, with varying levels of detail
    \item \textbf{Responsive Design:} Modern sites prioritize mobile-first approach
    \item \textbf{Content Organization:} Clear separation between academics, admissions, and administration
    \item \textbf{Visual Design:} Trend towards minimalism with accent colors reflecting institutional identity
\end{enumerate}

\subsection*{Identified Gaps}
\begin{itemize}
    \item Lack of advanced filtering in faculty directories
    \item Poor mobile experience on many institutional sites
    \item Outdated design aesthetics
    \item Slow loading times due to unoptimized images
    \item Limited interactivity and engagement features
\end{itemize}

These insights informed design decisions and feature prioritization for the NIT Goa website.

\chapter{System Architecture \& Design}

\section{High-Level Architecture}

The NIT Goa website follows a modern three-tier architecture pattern, separating concerns between presentation, business logic, and data layers. This architecture ensures scalability, maintainability, and clear separation of responsibilities.

\subsection*{Architecture Overview}

\begin{figure}[H]
    \centering
    \includegraphics[width=1\textwidth]{report/architectural_diagram.png}
    \caption{Three-tier architecture of the NIT Goa website}
    \label{fig:architecture}
\end{figure}


\subsection*{Key Architectural Decisions}

\subsubsection*{1. Monorepo Structure}
The project uses a monorepo approach managed by npm workspaces, providing:
\begin{itemize}
    \item Unified version control
    \item Shared dependencies and configurations
    \item Easier code sharing between frontend and backend
    \item Simplified deployment pipeline
\end{itemize}

\subsubsection*{2. Single Page Application (SPA)}
React-based SPA architecture offers:
\begin{itemize}
    \item Smooth, app-like user experience
    \item Faster navigation without full page reloads
    \item Efficient client-side routing
    \item Better performance through code splitting
\end{itemize}

\subsubsection*{3. RESTful API Design}
Backend follows REST principles:
\begin{itemize}
    \item Stateless server design
    \item Standard HTTP methods (GET, POST, PUT, DELETE)
    \item Resource-based URL structure
    \item JSON data format
\end{itemize}

\subsubsection*{4. Separation of Concerns}
Clear boundaries between layers:
\begin{itemize}
    \item Presentation logic in React components
    \item Business logic in Express routes/controllers
    \item Data access through database models
    \item Cross-cutting concerns in middleware
\end{itemize}

import React, { useState, useEffect } from 'react';
import './HeroCarousel.css';

const HeroCarousel = ({ images }) => {
  const [currentIndex, setCurrentIndex] = useState(0);

  useEffect(() => {
    const interval = setInterval(() => {
      setCurrentIndex((prevIndex) => 
        (prevIndex + 1) % images.length
      );
    }, 5000); // Auto-advance every 5 seconds

    return () => clearInterval(interval);
  }, [images.length]);

  const goToSlide = (index) => {
    setCurrentIndex(index);
  };

  const goToPrevious = () => {
    setCurrentIndex((prevIndex) => 
      prevIndex === 0 ? images.length - 1 : prevIndex - 1
    );
  };

  const goToNext = () => {
    setCurrentIndex((prevIndex) => 
      (prevIndex + 1) % images.length
    );
  };

  return (
    <div className="carousel-container">
      <div className="carousel-wrapper">
        <button 
          className="carousel-btn prev" 
          onClick={goToPrevious}
          aria-label="Previous slide"
        >
          &#8249;
        </button>
        
        <div className="carousel-content">
          <img
            src={images[currentIndex]}
            alt={`Slide ${currentIndex + 1}`}
            className="carousel-image"
            loading="lazy"
          />
        </div>

        <button 
          className="carousel-btn next" 
          onClick={goToNext}
          aria-label="Next slide"
        >
          &#8250;
        </button>
      </div>

      <div className="carousel-indicators">
        {images.map((_, index) => (
          <button
            key={index}
            className={`indicator ${
              index === currentIndex ? 'active' : ''
            }`}
            onClick={() => goToSlide(index)}
            aria-label={`Go to slide ${index + 1}`}
          />
        ))}

};

import React, { useState, useEffect } from 'react';
import FacultyCard from '../components/FacultyCard';
import './Faculty.css';

const Faculty = () => {
  const [facultyData, setFacultyData] = useState([]);
  const [filteredFaculty, setFilteredFaculty] = useState([]);
  const [selectedDepartment, setSelectedDepartment] = useState('all');
  const [loading, setLoading] = useState(true);

  const departments = [
    'All Departments',
    'Computer Science & Engineering',
    'Electronics & Communication Engineering',
    'Electrical & Electronics Engineering',
    'Civil Engineering',
    'Mechanical Engineering',
    'Mathematics',
    'Physics'
  ];

  useEffect(() => {
    fetchFacultyData();
  }, []);

  const fetchFacultyData = async () => {
    try {
      // In production, this would be an API call
      // const response = await axios.get('/api/faculty');
      // setFacultyData(response.data);
      
      // For now, using imported data
      const data = require('../data/faculty.json');
      setFacultyData(data);
      setFilteredFaculty(data);
      setLoading(false);
    } catch (error) {
      console.error('Error fetching faculty data:', error);
      setLoading(false);
    }
  };

  const handleDepartmentChange = (event) => {
    const department = event.target.value;
    setSelectedDepartment(department);

    if (department === 'all') {
      setFilteredFaculty(facultyData);
    } else {
      const filtered = facultyData.filter(
        (faculty) => faculty.department === department
      );
      setFilteredFaculty(filtered);
    }
  };

  if (loading) {
    return <div className="loading">Loading faculty data...</div>;
  }

  // Separate HODs and regular faculty
  const hods = filteredFaculty.filter(f => f.isHOD);
  const regularFaculty = filteredFaculty.filter(f => !f.isHOD);

  return (
    <div className="faculty-page">
      <div className="faculty-header">
        <h1>Faculty Directory</h1>
        <p>Meet our distinguished faculty members</p>
      </div>

      <div className="filter-section">
        <label htmlFor="department-filter">Filter by Department:</label>
        <select
          id="department-filter"
          value={selectedDepartment}
          onChange={handleDepartmentChange}
        >
          <option value="all">All Departments</option>
          {departments.map((dept, index) => (
            <option key={index} value={dept}>
              {dept}
            </option>
          ))}
        </select>
      </div>

      {hods.length > 0 && (
        <div className="hod-section">
          <h2>Heads of Departments</h2>
          <div className="faculty-grid">
            {hods.map((faculty) => (
              <FacultyCard 
                key={faculty.id} 
                faculty={faculty} 
                isHOD={true} 
              />
            ))}
          </div>
        </div>
      )}

      <div className="faculty-section">
        <h2>Faculty Members</h2>
        <div className="faculty-grid">
          {regularFaculty.map((faculty) => (
            <FacultyCard 
              key={faculty.id} 
              faculty={faculty} 
              isHOD={false} 
            />
          ))}
        </div>
      </div>

      {filteredFaculty.length === 0 && (
        <div className="no-results">
          No faculty members found for selected department.
        </div>
      )}
    </div>
  );
};

\begin{lstlisting}[language=JavaScript, caption=Faculty Controller with Database Queries]
const db = require('../config/database');

class FacultyController {
  // Get all faculty members
  static async getAllFaculty(req, res) {
    try {
      const [faculty] = await db.execute(`
        SELECT f.*, d.name as department_name
        FROM faculty f
        LEFT JOIN departments d ON f.department_id = d.id
        ORDER BY f.is_hod DESC, f.name ASC
      `);

      res.json({
        success: true,
        count: faculty.length,
        data: faculty
      });
    } catch (error) {
      console.error('Error fetching faculty:', error);
      res.status(500).json({
        success: false,
        message: 'Error fetching faculty data'
      });
    }
  }

  // Get faculty by department
  static async getByDepartment(req, res) {
    try {
      const { dept } = req.params;
      
      const [faculty] = await db.execute(`
        SELECT f.*, d.name as department_name
        FROM faculty f
        LEFT JOIN departments d ON f.department_id = d.id
        WHERE d.code = ? OR d.name = ?
        ORDER BY f.is_hod DESC, f.name ASC
      `, [dept, dept]);

      res.json({
        success: true,
        department: dept,
        count: faculty.length,
        data: faculty
      });
    } catch (error) {
      console.error('Error fetching department faculty:', error);
      res.status(500).json({
        success: false,
        message: 'Error fetching faculty data'
      });
    }
  }

  // Create new faculty member
  static async createFaculty(req, res) {
    try {
      const {
        name, email, designation, department_id,
        research_areas, phone, qualification
      } = req.body;

      const [result] = await db.execute(`
        INSERT INTO faculty 
        (name, email, designation, department_id, 
         research_areas, phone, qualification)
        VALUES (?, ?, ?, ?, ?, ?, ?)
      `, [name, email, designation, department_id,
          research_areas, phone, qualification]);

      res.status(201).json({
        success: true,
        message: 'Faculty member created successfully',
        data: { id: result.insertId }
      });
    } catch (error) {
      console.error('Error creating faculty:', error);
      res.status(500).json({
        success: false,
        message: 'Error creating faculty member'
      });
    }
  }
}

module.exports = FacultyController;

wait

\section{Technical Challenges}

\subsection{Challenge 1: Cross-Platform Development Scripts}

\subsubsection*{Problem}
Development team members used both Windows and Unix-based systems. The npm scripts didn't work consistently across platforms, particularly for:
\begin{itemize}
    \item Port cleanup (killing processes)
    \item Path separators (forward vs backslash)
    \item Concurrent process management
    \item Environment variable syntax
\end{itemize}

\subsubsection*{Solution}
Created separate development scripts for each platform:
\begin{itemize}
    \item \texttt{dev.sh} for Unix/Mac using bash
    \item \texttt{dev.bat} for Windows using batch
    \item Documented usage in README
    \item Tested on multiple OS versions
\end{itemize}

\textbf{Impact:} Reduced setup time from 30+ minutes to under 5 minutes across all platforms.

\subsection{Challenge 2: Faculty Directory Performance}

\subsubsection*{Problem}
Initial implementation loaded all 75+ faculty profiles at once, causing:
\begin{itemize}
    \item Slow initial page load (4+ seconds)
    \item High memory consumption on mobile devices
    \item Poor user experience on slower connections
    \item Large bundle size
\end{itemize}

\subsubsection*{Solution}
Implemented multiple optimization techniques:
\begin{itemize}
    \item Lazy loading for images
    \item Virtual scrolling for large lists
    \item Pagination option (20 faculty per page)
    \item Image size optimization (200x200px standard)
    \item Browser caching for faculty data
\end{itemize}

\textbf{Impact:} Reduced page load time to 2.4 seconds, 40\% improvement.

\subsection{Challenge 3: Responsive Image Carousel}

\subsubsection*{Problem}
The 17-image homepage carousel faced several issues:
\begin{itemize}
    \item Different image aspect ratios causing layout shifts
    \item Large image files (2-3MB each) slowing page load
    \item Carousel height jumping on mobile devices
    \item Touch gestures not working smoothly
\end{itemize}

\subsubsection*{Solution}
\begin{enumerate}
    \item Standardized all images to 16:9 aspect ratio
    \item Compressed images using ImageOptim (reduced to 200-300KB)
    \item Created multiple image sizes for different devices
    \item Implemented touch event handlers for swipe gestures
    \item Fixed carousel container height with CSS
\end{enumerate}

\textbf{Impact:} Improved LCP from 3.8s to 2.1s, eliminated layout shift.

\subsection{Challenge 4: Department Filtering Logic}

\subsubsection*{Problem}
Faculty filtering by department had edge cases:
\begin{itemize}
    \item Some faculty belonged to multiple departments
    \item HODs needed special handling in filtered results
    \item Filter state not persisting on page refresh
    \item URL not reflecting current filter
\end{itemize}

\subsubsection*{Solution}
\begin{lstlisting}[language=JavaScript, caption=Enhanced Filtering Logic]
const filterFaculty = (department) => {
  if (department === 'all') {
    return facultyData;
  }
  
  const filtered = facultyData.filter(faculty => {
    // Check primary department
    if (faculty.department === department) return true;
    
    // Check additional departments (if any)
    if (faculty.additionalDepts?.includes(department)) return true;
    
    return false;
  });
  
  // Separate HODs for priority display
  const hods = filtered.filter(f => f.isHOD);
  const regular = filtered.filter(f => !f.isHOD);
  
  return [...hods, ...regular];
};
\end{lstlisting}

\textbf{Impact:} Accurate filtering with zero edge case failures in testing.

\section{Express.js API Endpoint}

\begin{lstlisting}[language=JavaScript, caption=Faculty API Endpoint]
const express = require('express');
const router = express.Router();
const db = require('../config/database');

// Get all faculty members
router.get('/faculty', async (req, res) => {
  try {
    const { department } = req.query;
    
    let query = 'SELECT * FROM faculty';
    let params = [];
    
    if (department) {
      query += ' WHERE department = ?';
      params.push(department);
    }
    
    query += ' ORDER BY isHOD DESC, name ASC';
    
    const [faculty] = await db.execute(query, params);
    
    res.json({
      success: true,
      count: faculty.length,
      data: faculty
    });
  } catch (error) {
    console.error('Error fetching faculty:', error);
    res.status(500).json({
      success: false,
      message: 'Server error'
    });
  }
});

module.exports = router;
\end{lstlisting}

CREATE TABLE faculty (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    designation VARCHAR(100),
    department VARCHAR(100) NOT NULL,
    photo_url VARCHAR(500),
    research_areas TEXT,
    is_hod BOOLEAN DEFAULT FALSE,
    phone VARCHAR(20),
    qualification VARCHAR(255),
    experience INT,
    publications TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
